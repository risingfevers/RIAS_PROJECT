Lakehouse и Feature Store реализация#### 4.1. Трёхуровневое хранилище (Medallion Architecture)| Слой | Назначение | Формат | ACID-подход ||------|-----------|--------|-------------|| **Bronze** | Сырые события вовлечённости | Parquet | Версионирование через timestamp + hash || **Silver** | Очищенные, валидированные, агрегированные данные | Parquet | Транзакционные логи в `_transactions/` || **Gold** | Обогащённые признаки для аналитики и ML | Parquet | Версионирование, витрины данных |#### 4.2. Имитация ACID-транзакцийВ условиях отсутствия Apache Spark реализован механизм версионирования:- Каждая запись данных получает уникальную версию (hash + timestamp)- Транзакционный лог сохраняется в поддиректории `_transactions/`- Возможность отката к предыдущей версии через логи#### 4.3. Feature Store**Выделенные признаки для ML модели** (прогноз успеваемости):1. `total_events` — общее количество событий вовлечённости2. `most_common_action` — наиболее частый тип действий3. `avg_activity_hour` — средний час активности4. `weekend_activity_ratio` — доля активности в выходные5. `average_grade` — средняя оценка (добавлен из домена academic_performance)**Целевая переменная:** `passing_grade` (1 — успевает, 0 — риск отчисления)**Feature Registry** сохранён в MinIO: `feature-store/feature_registry.json`#### 4.4. Materialization- **Пакетная материализация** (hourly) — данные для обучения- **Online store** (имитация) — JSON-формат для low-latency доступа#### 4.5.
